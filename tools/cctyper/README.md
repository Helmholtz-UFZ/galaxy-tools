# CRISPRCasTyper

Galaxy wrapper for [CRISPRCasTyper](https://github.com/Russel88/CRISPRCasTyper)
(`cctyper`), which identifies, annotates and subtypes CRISPR-Cas loci in
nucleotide sequences.

## Input and output

A nucleotide FASTA file (plain or gzipped, one or more sequences, each analysed
separately). Optional parameters control circular replicons, the gene prediction
mode, the Cas operon and array cut-offs, and whether a map is drawn.

Reported are the CRISPR-Cas loci, all Cas operons, all CRISPR arrays (as table
and as GFF3) and an optional SVG map. Everything cctyper writes in addition is
returned as one collection, so nothing is lost. Empty result tables are written
header-only when nothing was found, which keeps the outputs usable in
workflows.

## Implementation

`cctyper_galaxy.py` runs cctyper with the arguments generated by the wrapper and
normalises its output directory, which cctyper only fills with the files it has
data for:

* header-only versions of the main tables (plus an empty GFF3) are written when
  cctyper did not create them,
* a placeholder SVG is written when a map was requested but there was nothing to
  draw,
* all remaining files are moved into `results/extras/` for collection discovery.

Two limits of cctyper 1.9.0 are handled in the wrapper:

* an input without a single Cas HMM hit ends in
  `KeyError: "['Hmm', 'ORF'] not in index"` (`hmmer.py:290`). That is a valid
  input, so the wrapper writes the empty result tables, keeps the traceback in
  `extras/cctyper_stderr.log` and reports a warning instead of failing the job.
* pyrodigal cannot train a gene model on sequences shorter than 20 kb and raises
  (`prodigal.py:33`). The `auto` gene prediction mode therefore selects the
  metagenomic model when no sequence reaches that length.

cctyper 1.9.0 also exits with status 0 for several errors (`controller.py:252`,
`hmmer.py:301` call bare `sys.exit()`), so `detect_errors` stays at `exit_code`
and the wrapper verifies that the run reached its final step
(`Removing temporary files`) before the job is reported as successful.

## Reference data

cctyper 1.9.0 ships the Cas HMM profiles, the repeat classifier, the scoring
tables and the known repeats inside the package (`cctyper/data`), so the wrapper
neither downloads nor configures a database. The database is therefore pinned to
the conda package and identical for every run of a given tool version.

To use a different database, set `CCTYPER_DB` in the job environment to a
directory that contains `cctyper_profiles.hmm` (or `cctyper_profiles.hmm.zst`),
`CasScoring.csv`, `xgb_repeats.model` (or `.json`/`.ubj`), `type_dict.tab`,
`cutoffs.tab`, `interference.json`, `adaptation.json` and `repeats.fa`. cctyper
resolves `--db` > `CCTYPER_DB` > packaged data (`resources.py:5-33`). Note that
`--custom_hmm` only decorates the map, it does not add profiles to the Cas
search.

## Requirements

* `cctyper` 1.9.0 from bioconda. It brings BLAST+, which the default repeat
  search backend needs; the bundled `myers` and `edlib` backends need no
  external program.
* Galaxy 25.0 or newer (profile 25.0).

## Testing

```sh
planemo lint cctyper.xml
planemo shed_lint --fail_level error .
planemo test --galaxy_python_version 3.12 cctyper.xml
```

The tests cover a bacterial genome with a type I-E locus (map drawn, BLAST+
backend), a gzipped *Streptococcus pyogenes* fragment with a type I-C and a
type II-A locus (circular, `myers` backend, no map) and a 6 kb sequence without
any Cas gene (empty results, warning).
